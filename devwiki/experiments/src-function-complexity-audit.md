# Source function-size and complexity audit

## Purpose

Establish a reproducible baseline for human review of source-code maintainability. The audit is diagnostic only: it does not refactor code, enforce thresholds, or establish a style policy.

## Method

The `scripts/audit_src_complexity.py` script combines Radon's cyclomatic-complexity report with source-span line counts and a supplementary AST-based maximum control-flow nesting measure. It scans Python files under `src/`.

The CI workflow publishes the generated Markdown report in the job summary and as the `source-complexity-audit` artifact. The report is tied to the commit tested by that workflow. For a local snapshot, install development dependencies and run:

```sh
python scripts/audit_src_complexity.py --output src-complexity-audit.md
```

## Interpretation

Rankings are triage aids, not quality judgements. Function length and cyclomatic complexity measure different things; neither alone establishes that a function should be changed. The metrics do not capture responsibility boundaries, domain difficulty, naming, or adequacy of tests. Human review is needed before drawing conclusions.

No hard limits or automated failure conditions are proposed by this audit itself. The separate blocking policy is documented in [[devwiki/process/development-workflow#complexity-ratchet]]. Any future action based on the findings should be considered separately.

## Baseline record

The baseline report is generated by CI for the relevant commit. Review the artifact and workflow summary attached to the audit PR before recording numerical findings here. This page intentionally does not invent or pre-empt those measurements.
